### Incident: Flux 2.9 strict post-build substitution (fixed in Git)

kustomize-controller 1.9 enables `StrictPostBuildSubstitutions` by default. After the upgrade, `cluster-apps-vector` failed to build:

> variable not set (strict mode): "SVC_VECTOR_ADDR"

`helm-aggregator.yaml` referenced `${SVC_VECTOR_ADDR}`, which was never defined in cluster-settings or cluster-secrets. Flux 2.8 had substituted it with an empty value, so the live `loadBalancerIP` was null and Cilium LB-IPAM assigns `.203`. Only that Kustomization was blocked; the running vector workloads were unaffected.

The fix in `c93b0f2` uses `${SVC_VECTOR_ADDR:=}`, which renders exactly as before:
- the HelmRelease generation stayed at 5 and its revision at 1
- there was no Helm upgrade
- the Service kept `.203`

A repo-wide scan found no other undefined variable. The remaining `${...}` hits are shell variables, either `$$`-escaped or in Kustomizations with substitution disabled.

This was not caught beforehand because the server dry-run checks the Flux manifests themselves, not the substitution behaviour of the new controller.
